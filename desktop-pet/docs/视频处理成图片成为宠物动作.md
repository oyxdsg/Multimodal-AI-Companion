# 视频处理成图片成为宠物动作 的具体方法

> 本文档说明桌宠（Desktop Pet）如何把一段**绿幕动作视频**，转成可在桌面上播放的**宠物动作**（透明 PNG 帧序列），并接入动画系统。适用于 `素材源/` 里常见的绿幕动作视频（`思考.mp4`、`开心跳舞.mp4`、`害羞动作.mp4`、`惊讶动作.mp4`、`站着睡着.mp4`、`开心跳起.mp4`、`打滚.mp4` 等）。

---

## 0. 目标

把一视频变成一组 `.png` 帧，播放时满足：

1. **透明背景**：绿幕被抠掉，只留角色。
2. **大小统一**：所有动作的站姿等高（基准高度 `STAND_H`）。
3. **站立位置对齐**：各动作"站姿"停在同一位置（切换动作不闪烁）。
4. **不漂移**：动作播放时角色脚 x 坐标保持不变（不被尾巴/裙摆拖偏）。
5. **保留真实位移**：像「跳跃」「打滚」这类带整体位移的动作，能还原"跳起/翻滚"的运动，而不是原地鬼畜。

---

## 1. 素材来源与格式

- 绿幕视频：背景为纯绿（RGB 约 `(19,207,27)`，`768×1344` 或 `720×1280`，24fps，约 97~107 帧）。
- 角色：以"站立姿态"为**首尾参考**（每个视频首尾帧角色都处于站立姿，便于对齐）。
- 素材目录：`素材源/` 与 `素材源/新素材/`。

---

## 2. 总流程

```
绿幕视频.mp4
   │ ① 色度键抠图（去背景）
   ▼
RGBA 帧（透明背景，角色在画面原位置）
   │ ② 站姿大小统一（按首帧站立高度定缩放 scale）
   ▼
等比例缩放后的帧
   │ ③ 不动点（脚底）对齐：整体平移 dx,dy（由首帧脚底锚点定）
   ▼
对齐到"正面站立"站位基准的帧（512×512 画布，贴底、水平固定）
   │ ④ 位移动作：额外记录垂直轨迹 traj
   ▼
assets/<动作>/frame_XXXX.png  +  (可选) traj.json
   │ ⑤ 桌宠渲染接入（_load_actions 施加轨迹）
   ▼
桌面上播放的宠物动作
```

## 3. ① 绿幕抠图（色度键 Chroma Key）

对每一帧做以下处理，得到带 alpha 的 RGBA。

### 3.1 估计背景色
取帧**顶部 10% 高度**条带的像素**中位数**作为背景绿 `bg`。绿幕通常很均匀，中位数抗噪。

### 3.2 色差 → 软 alpha
计算每个像素与 `bg` 的欧氏距离 `d`，用两条软阈值映射到 `0~1`：

```
d        = sqrt( (R-bgR)^2 + (G-bgG)^2 + (B-bgB)^2 )
alpha_soft = clip( (d - LOW) / (HIGH - LOW), 0, 1 )
→ 角色(d 大) alpha≈1；背景(d≈0) alpha≈0；边缘软过渡。
常用 LOW=35, HIGH=95。
```

### 3.3 连通域保护（关键：别把角色身上颜色抠掉）
仅靠色度键会把角色身上**接近绿色的像素**（白裙子阴影、蓝绿色反光）误抠。做法：
- 取 `alpha>0.4` 作前景种子 → 形态学开/闭运算去噪补洞。
- **保留最大连通域**作为角色主体，将其内部强制 alpha=1（`body_filled`）。
- 最终 `alpha = max(alpha_soft, body_filled)`：主体恒不透明，边缘保留软过渡。

### 3.4 去绿溢色（despill）
角色边缘会"吸"到绿幕光（绿边）。对 alpha 越小的像素越多扣绿：

```
spill = clip( G - max(R,B), 0, None )      # 仅针对绿色溢出量
G'    = G - spill × (1 - alpha)            # 主体(alpha=1)不扣，边缘多扣
```
这样蓝发/蓝裙/白裙/肤色都不受影响（它们 G 并未超 max(R,B)）。

### 3.5 水印 / 地面阴影清理
绿色水印、角色脚下的绿影，用"**绿色显著占优**"判据压透明（不限亮度）：

```
residual = (G > B + 6) & (G > R + 6)
alpha    = where(residual, alpha × 0.04, alpha)
```
因为蓝发/蓝裙是 **B 占优**、白裙是 R≈B、肤色是 R 占优，都不会被误伤；只有真正偏绿才会被清掉。

再对 `alpha>0.35` 做**连通域面积过滤**（面积 `<2000` 的小块清空），去掉水印文字、孤立噪点。

### 3.6 边缘羽化
对 alpha 做一次轻微高斯模糊（σ≈1），让发丝/裙边更自然。

> 注意：OpenCV 的 `imread/imwrite` 在 Windows 下**不支持中文路径**，读取视频用 `cv2.VideoCapture`（支持），但**保存 PNG 请改用 `PIL.Image.fromarray(...).save(...)`**。

## 4. ② 站姿大小统一

取**首帧**（站立姿）内容包围盒高度 `h0`，计算统一缩放：

```
scale = STAND_H / h0        # STAND_H = 480（站姿内容高度基准，与正面/背面/侧面一致）
```

之后整段视频所有帧都用这个 `scale`（等比例缩放）。这样**同一视频内大小一致**，且首帧站姿恰好 480 高，与其它站姿动作等高。

---

## 5. ③ 不动点（脚底）对齐

这是解决"漂移"和"站立不齐"的核心。**不要对每帧单独算质心/bbox 对齐**（那样会被大裙摆、鱼尾拖偏，导致角色左右漂移），而是：

### 5.1 选锚点：脚底贴地窄带中心
对每帧，取**内容包围盒最底端窄带**（约内容高 4%）的非零像素加权质心作为**脚底锚点** `P=(px0, py0)`：
- 它是"贴地"的点，只含鞋底，**不含悬空的尾巴/裙摆**。
- `px0` 反映双脚水平位置；`py0` 反映脚底高度（跳跃时脚抬起 → `py0` 变小）。

### 5.2 首帧定基准（整段动作**整体平移**）
用**首帧**锚点 `(ax0, ay0)` 定出整段动作的一个**统一平移量** `dx, dy`：

```
scale   = 480 / 首帧内容高
dx      = FOOT_TARGET - ax0 × scale            # 让锚点x 对齐到"正面站立站位"
dy      = CANVAS - ay0 × scale                 # 让首帧脚底 贴画布底
```

其中：
- `FOOT_TARGET`：站姿站立站位基准。取桌面正面的「脚底位移」：
  ```
  正面：脚底质心 230.5 − 20%质心 276.9 = −46.4
  FOOT_TARGET = 256 + (−46.4) = 209.6
  ```
  这样所有新动作的脚底，在桌宠渲染后都落在与"正面"相同的位置（切换不闪）。
- `CANVAS = 512`（统一画布边长）。

### 5.3 每帧放置（保持原视频帧间关系 → 零漂移）
整段动作都用同一个 `dx, dy`，每帧内容按其原视频包围盒左上角映射到画布：

```
画布x = bbox.left × scale + dx
画布y = bbox.top  × scale + dy
```

因为 `dx, dy` 是**常量**，所以：
- 帧间相对位置 = **原视频的真实相对位置** → 角色脚 x 恒定、动作内零漂移。
- 首帧双脚对齐到 `FOOT_TARGET`（≈正面站位）→ 各动作站姿一致。

> 之所以"整体平移"而不是"逐帧对齐"：逐帧算质心去对齐，质心会被该帧尾巴/裙摆位置影响，帧间就抖；用首帧锚点+常量平移，动作内完全不动。

### 5.4 画布归一化
输出为 `CANVAS×CANVAS`（512×512）的透明画布，内容放进上述位置。桌宠读取时会再按内容包围盒裁剪，画布大小不影响显示。

## 6. ④ 位移动作的运动轨迹（以跳跃为例）

跳跃这类动作角色有**整体位移**（跳起-落下）。若按上面"贴底对齐"，角色会一直贴地，跳起信息丢失。所以额外提取一条**垂直轨迹**并写回渲染。

### 6.1 轨迹提取
```
锚点 y = 该帧脚底窄带高度（内容底端 y）
dy_i   = (首帧脚底y − 该帧脚底y) × scale   # 脚离地高度，>0 表示跳起
水平：不允许移动 → 锚点 x 用首帧 ax0（恒定），水平轨迹恒为 0
```

### 6.2 轨迹存储
写入 `assets/<动作>/traj.json`，结构为每条一个对象：

```json
[
  {"dy": 0.0},
  {"dy": 12.4},
  {"dy": 42.7},
  {"dy": 50.0},
  ...
  {"dy": 0.0}
]
```

### 6.3 桌宠渲染时施加
桌宠 `_load_actions` 生成显示帧时，把内容**贴底**后减去 `dy_i`（向上位移），并 clamp 到画布内：

```
py = 画布高 − 内容高 − round(dy_i × scale)
py = max(0, min(py, 画布高 − 内容高))    # 保证内容完整不出界
```

这样角色在播放时**真实地跳起-落下**，水平不动。

### 6.4 打滚（含旋转 / 大幅位移的多阶段动作）

打滚 = 站立 → 倒地 → 翻滚 → 起身，内含**大幅横移 + 旋转**。这里**不能用「脚底」当不动点**（翻滚中脚朝天、朝向乱变，脚底窄带检测会飘），改用**角色中心**：

- **不动点**：内容包围盒中心 `C=(cx, cy)`（连贯、可追踪）；旋转由**帧内容自身**表现。
- **轨迹**：每帧中心相对首帧中心的偏移，写到 `traj.json`：
  ```json
  [{"dx": 0.0, "dy": 0.0}, {"dx": -12.4, "dy": 3.1}, ..., {"dx": 0.7, "dy": 0.0}]
  ```
  `dx` 记录横向（向左滚再回），`dy` 记录纵向（倒地中心下沉/起身回升）。打滚首尾站立中心一致，轨迹近**闭合**。
- **帧生成**：内容中心放画布中心（居中）。
- **桌宠渲染**：对轨迹**含 `dx` 的动作**用「内容中心放置 + (dx,dy)」：
  ```
  px = 画布中心水平 − 内容中心偏移 · scale + dx·scale
  py = 画布中心垂直 − 内容高/2     + dy·scale
  ```
  这样角色中心随轨迹移动（向左滚过去再回来），旋转由帧自带。仅含 `dy` 的（跳跃）仍走「贴底 + 上移」。

> 打滚与跳跃共用一套"位移动作"机制，区别只在不动点（脚底 vs 角色中心）与轨迹维度（仅 dy vs (dx,dy)）。

## 7. ⑤ 桌宠渲染接入

### 7.1 `config.py`
- `ACTIONS` 加动作映射：`"shy":"害羞"`, `"surprised":"惊讶"`, `"sleep":"站着睡着"`, `"jump":"跳跃"`。
- `PRE_ALIGNED` 加这些动作 key：表示它们走**独立脚心定位**（`_foot_center_x_narrow`），其余姿势仍走全局 `_foot_center_x`。
- `AI_ACTION_TAGS` 加：`"害羞":"shy"`, `"惊讶":"surprised"`, `"睡眠":"sleep"`, `"跳跃":"jump"`。

### 7.2 `pet_anim.py`
- `_foot_center_x_narrow(img)`：对 `PRE_ALIGNED` 动作返回**素材画布宽度中心** `img.width()/2`（恒定值）。因为这些素材已"整体平移"把站姿中轴固定在画布中心，桌宠只需把素材整体位置映射到画面中心，**不逐帧算质心**（质心会因尾巴/裙摆漂移）。
- `_load_actions`：加载该动作目录下的 `traj.json`，在生成显示帧时按上式施加垂直轨迹。

### 7.3 `pet_window.py`
- 加状态常量（`STATE_SHY/SURPRISED/SLEEP/JUMP`）。
- 加入 `_STAND_POSTURE`（站姿组）与 `_ONESHOT`（一次性动画，播完回待机）。
- 右键「🎬 动作」菜单加对应项。

### 7.4 坐姿↔站姿过渡
`pet_anim._build_chain` 自带过渡链：坐姿→站姿自动插「起身 RISE」、站姿→坐姿插「坐下 SIT」，新动作属于站姿组即可正确衔接。

## 8. 数据格式小结

```
assets/
├── 思考/  frame_0000.png ...（97帧，512×512，脚底对齐正面站位）
├── 哭泣/
├── 开心/
├── 害羞/
├── 惊讶/
├── 站着睡着/
├── 打滚/
        frame_0000.png ...（107帧，内容中心居中）
        traj.json                # 每帧中心轨迹 (dx,dy)
└── 跳跃/
        frame_0000.png ...（107帧）
        traj.json                # 每帧垂直位移 (dy)
```

- 帧文件：`frame_XXXX.png`，透明背景，尺寸可任意（桌宠按内容包围盒裁剪+缩放）。
- 位移动作：同目录 `traj.json`，`[{dy:...}, ...]`，与帧一一对应。

## 9. 关键坑点与经验

- **尾巴/裙摆会把"质心"拖偏** → 不要用"底部 20% 质心"或"内容 bbox 中心"当脚心；用**内容最底端窄带（贴地脚底）**，天然排除悬空尾巴。
- **不要逐帧对齐，要整体平移** → 逐帧算锚点去对齐会让帧间抖动；用首帧锚点 + 统一位移，动作内零漂移。
- **与桌宠定位算法保持一致** → 素材用的锚点算法要跟桌宠读的保持一致，否则"双重对齐"反而引入漂移。
- **OpenCV 中文路径** → 保存 PNG 用 PIL；`cv2.imwrite` 对中文路径在 Windows 会失败。
- **首尾站立呼应** → 视频首尾帧是站立姿，缩放到 `STAND_H` 站姿高度，保证与其它站姿动作等高、可衔接。
- **跳跃幅度受画布顶部留白限制** → 若最高点碰到画布顶，会 clamp 压缩一点跳起幅度，可按需给位移动作单独加顶部留白。
