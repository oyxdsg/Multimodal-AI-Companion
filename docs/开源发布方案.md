## 二、RAG 项目 = 桌宠的知识插件（定位纠偏 + 落地）

### 2.1 定位纠偏

`RAG方案/mcwiki-agentic-rag`（与本仓库同级的独立目录，**非 git 仓库**）**不是外部参考项目，而是桌宠的知识插件（重型版）**。

修正前我（及 `DESIGN_AI_ROADMAP.md`）把它写成「外部参考、只借鉴理念、不构成依赖」——
那只描述了 **2.30.0 那一轮的借鉴关系**，没描述它的**归属**。正确表述：

```
桌宠 wiki-knowledge 扩展点  ←── 两个可选实现
        ├── wiki-local   （轻量：纯词法 + 本地精炼小模型，零重依赖）
        └── agentic-rag  （重型：向量 + BM25 + RRF + 规则重排 + ReAct，需 faiss/torch）
```

**它们不是竞品，是同一扩展点的两档实现**，用户按机器条件二选一。

### 2.2 打包方案

| 项 | 取值 |
|---|---|
| 插件 id | `agentic-rag` |
| 插件仓库 | **不单开** —— 随本仓库发布（单仓库策略） |
| 目录 | `desktop-pet/plugins/agentic-rag/`（插件**代码入库**；数据 / `.venv` 不入库） |
| Python 模块 | `deskpet_plugin_agentic_rag` |
| 扩展点 | `type: ["wiki-knowledge"]` |
| 入口 | `plugin.py:register` → `host.add_wiki_knowledge(AgenticRag())` |
| `requires` | `faiss-cpu` `sentence-transformers` `jieba` `mwparserfromhell` `torch`（宿主只提示、不代装） |
| 数据 | 56.4MB 原文 + 25.7MB chunks + 180MB faiss + 82.7MB BM25 ≈ **345MB，一律不入库**，由插件自带脚本重建 |

接口实现（对齐 `PLUGIN_API.md §2.1`，**宿主零改动**）：

```python
class AgenticRag:
    def know(self, events_text, *, session_key="", max_chars=480, hints=()):
        # 复用 RAG 项目既有链路：
        #   rules.py/NLU（need + page_type）→ retrieve.py（向量 + BM25 + 元数据过滤）
        #   → rrf.py(k=60) 融合 → rerank.py 规则重排 → 裁剪到 max_chars → 返回文本
        # 命中不到 → 返回 None（宿主按"不注入"处理，大模型自答）
```

**要改的三处耦合**：

1. `tools/export_creds.py` 从桌宠 `QSettings` 抠 API Key —— **插件不该伸手进宿主的凭据库**。
   `know()` 本身**不需要 LLM**，可直接删掉这条依赖。
2. 它自己的 `nlu_*` 微模型与桌宠 `nlu/` 是两份实现 —— 作为插件应**自带**，不再指回宿主。
3. 硬编码路径（沿用 wiki-local 的老办法：基于 `__file__` 推导）。

### 2.3 两个落地档位（建议先做 A）

| 档 | 内容 | 宿主改动 | 建议 |
|---|---|---|---|
| **A（先做）** | RAG 作为 `wiki-knowledge` 的重型实现，只提供**知识注入增强**（更准的召回/排序） | **零改动** | ✅ 立即可落地 |
| **B（后续）** | 把它的 Agentic 问答 / ReAct / 图片理解暴露成桌宠新能力（用户直接问"下界合金锭怎么合成"） | 需新增扩展点 `knowledge-qa`，或给 `HostAPI` 加可选 `llm()` 通道（接口只增不改） | ⏳ 需要一次宿主设计 |
