**Multimodal-AI-Companion** —— 一个住在你桌面上的鲸鱼女仆：有丰富动作、能陪你聊天、支持语音对话、
支持图片上传，会陪你打 Minecraft，还能变成游戏里的女仆陪你玩。形象是经典大肥鱼形象，
你也可以替换为你喜欢的角色形象，形象来自 b 站 up 主 zipzippipe。

具体刚刚开源，欢迎大家下载安装和反馈问题。

* 主体仓库（clone 约 4MB，装完就能跑）：<https://github.com/oyxdsg/Multimodal-AI-Companion>
* 动画资源（约 247MB，想要动画再下）：<https://github.com/oyxdsg/Multimodal-AI-Companion-Assets>
* 最新版本（v2.31.0）：<https://github.com/oyxdsg/Multimodal-AI-Companion/releases/tag/v2.31.0>

MIT 许可，插件接口完全公开。

**开发成本**：大约**一个月的业余时间**，我负责设计框架和架构以及技术路线，具体代码块使用 vibe coding
辅助完成。大部分都是 deepseek 做的（v4.1 太好用了），原来订阅的 opencode，后来居然涨到 10 刀，
用不起了，转了火山引擎的 coding plan，虽然没有 v4.1 但是量大管饱。

## 一、起因：一次刷贴吧的偶遇

做这个项目的原因说出来你可能不信：大肥鱼太可爱了！

一次刷贴吧偶然的点击 deepseek 吧，发现 8u 发的大肥鱼表情图，当时完全被 cute 到了，
就那几天我的 b 站全是大肥鱼的视频（被大数据和算法拿捏了）。

当时我就想：能不能把这个小东西做成桌宠呢，一个能陪我玩游戏的桌宠，说干就干。

桌宠这个东西我用过不少，问题还挺一致：

* **好看的不会说话**，新鲜两天，第三天你就不再点它了；
* **会说话的只是个聊天框**，被挪到了桌面角落。你问它答，但它跟你的生活没什么关系。

我想要的是第三种：**你真的能感觉到她在陪你。**

说具体点，是三件事：

1. **感知** —— 你打游戏的时候，它知道你在干什么；
2. **行动** —— 你说话的时候，它听得懂，而且真的能替你做点什么；
3. **分寸** —— 你忙的时候，它自己待着，不来打扰你。

这三件事单看都不难，凑到一起就很难——因为它们是互相打架的：越能感知越容易烦人，
越能行动越容易闯祸。

这一个月，大部分时间其实都花在这三件事的平衡上。

## 二、它现在能做什么

先说最直观的：她能陪你玩游戏，目前只支持 mc，未来会更新更多的游戏接口。
基于 token 节约设计，AI 只负责发指令和与你聊天，指令下发后本地执行，大部分 token 都用于 prompt 上，
如果你想修改人设或者进一步压缩 token，可以直接修改 prompt。目前内设两种人格，
每个人格都支持完整版、精简模式、极简模式。

![游戏内画面](images/maid-ingame.png)

所有行为都在设置界面里配置，**一共 13 页，全部图形化，不用碰任何配置文件**：

![设置页面](images/settings-dialog.png)

### 在桌面上

她是一套逐帧动画的透明形象：会自己随机走动、会看你点击、能被你拖来拖去，右键有动作菜单，
亮度、对比度、饱和度可以实时调，也可以强制置顶不让窗口盖住她。
想换形象就换皮肤——动作素材、右键菜单、名字、人格设定会一起切过去。

### 聊天

支持 **AI 后端**随时切换，各家的 Key 和模型分别保存、互不覆盖，也可以接你自己的
OpenAI 兼容端点。内置多个人格可以选，对话有记忆，支持流式输出。
（如果你是学生或者不知道怎么接入 api，可以使用我们的 web 插件，只需要一个 deepseek 账号即可使用，
仅用于学习！）

支持**图片上传**——你完全可以直接把截图丢给她。

### 语音交流

* **朗读**：支持多种朗读方式，音色、语速、音量都能调；气泡和语音同步，免费的建议使用 EDGE TTS，
  虽然有一定延迟但是也能接受，如果想追求更好的对话质量，可以去阿里百炼注册一个账号，
  新人有三个月的免费模型用，创建一个 api 密钥就可以使用啦。
* **对话**：使用快捷键进行语音输入，默认键 Y，持续按住输入，松开发送消息，**离线识别**，
  不用联网、不上传录音。目前支持两种识别引擎，可以自行选用。

### 环境、工作与娱乐

* **环境提醒**：需要联网，读取最新的天气消息主动提醒你天气变化；
* **新闻播报**：需要联网，支持自定义导入新闻源，闲着的时候可以让桌宠给你念几条新闻；
* **工作模式**：静默陪伴，会输出一些工作小提示；
* **文字修仙**：内置了一个文字修仙小游戏，可以直接玩（作者自己手搓的，不喜勿喷）。

### 游戏联动（Minecraft）

这是我觉得最有意思的部分：

* **游戏内环境感知** —— 你挖到了什么、遇到了什么怪、天黑了还没睡、走丢了、背包快满了。
  模组自动监听游戏内关于你的信息和女仆自己的信息。wiki 插件支持女仆通过 RAG 来提取信息，
  更好的理解游戏与你交流。
* **支持建筑识别** —— 配套模组能识别建筑物的形制，给出风格判断和改进建议。
* **拥有玩家能力** —— 支持跑酷、挖掘，搭方块、替你挖矿打怪（你打怪不一定有女仆厉害），
  甚至能找到箱子、把东西带回来；支持自定义任务，比如砍树、挖矿，
  女仆会自己拆解组织任务然后执行。
* **可以把桌宠隐退，只留她当 AI 后端** —— 不占桌面，但游戏里的对话能力照样在。

## 三、几个优化设计

### 1、插件化

我们把核心功能保留在一个 4MB 大小的文件里，然后设计了接口规范，所有外置功能通过插件接入，
如果你也对这个项目感兴趣，欢迎制作属于你的插件！

很多软件的插件体系是「核心功能写死，插件当添头」。我一开始就反过来做：

**每一项可选能力，本体都自带一个最小实现。** 你把所有插件都删掉，她依然能启动、能聊天、
能进游戏模式。插件只负责「更好」，不负责「能用」。

### 2、通用 API 接口

只接一家 API 的项目，一旦那家的模型涨价、改名、或者接口调整，你就得跟着改，甚至整个不能用。

所以从一开始，供应商就是**可插拔**的。换后端不需要改代码，界面上切换就行；
各家语义不一样的地方（比如「思考」这个开关在不同模型上意思完全不同），也按模型分别记忆。

## 四、关于 vibe coding：我用它做了什么，它不管什么

这个项目绝大部分代码是我和 AI 一起写出来的，也就是大家说的 vibe coding。
一个月业余时间能做出这个体量，坦白说靠的就是它。

但我想说得更具体一点，因为它不是「输入需求就出软件」：

**它擅长的**：写模块、改界面、补边界情况、把我描述的逻辑翻成代码、帮我查一个报错的成因。
效率提升是实打实的，尤其是那种「我知道要写什么但懒得敲」的部分。

**它不管的**：方向、判断、验收。（设计架构和 debug 真的花很花时间 QAQ）。

* 架构怎么做？；
* 动画资源到底放进主仓库还是单独一个仓库？这决定了别人克隆的体验，也决定了许可证合不合法；
* 一个接口设计得对不对？得由后续所有代码来验证，而不是由生成它的模型来评价。

我踩过的坑基本都在这一层：AI 能很快给你一个「看起来能跑」的实现，
但**它不会告诉你这个实现三个月后会不会变成一个包袱**。

所以我的实际用法是：**我定结构和接口，AI 填实现；我负责验收，它负责快速产出。**
方向错了，写代码快十倍也没用。

## 五、开源，不只是发一个压缩包

现在这个仓库里，除了代码，还有：

* **完整的插件规范** —— 想给她加能力，不用改本体；
* **一个可以直接复制的插件示例** —— 大约一百行，改个名字就能跑起来；
* **一份贡献指南** —— 开发环境怎么搭、改完要跑什么、哪些约束不能破；
* **设计文档、测试报告和踩坑记录** —— 包括一些当时的错误结论，以及后来是怎么纠正的。

我特意保留了很多「过程」，因为这些通常才是最有用的部分。

顺便一提，为了让大家 clone 得舒服，公开出来的版本用的是**重新整理的干净历史**——
不会拖出一堆几百兆的旧文件；保留了本地的完整开发记录。

## 六、怎么开始

```bash
git clone https://github.com/oyxdsg/Multimodal-AI-Companion.git
pip install -r Multimodal-AI-Companion/desktop-pet/requirements.txt
python Multimodal-AI-Companion/desktop-pet/main.py
```

需要 **Python 3.10+**，目前主要在 Windows 上使用。

**首次启动是静态桌宠**，这是因为动画资源不随源码发布。
想要动画，去资源仓库下载压缩包，解压到指定目录就行；功能其实一样都不缺，只是不会动。

想和她说话，右键「设置」里选一家 AI 后端、填上 Key 就可以聊，**不需要装任何插件**。

想给她加功能，仓库里有一个约一百行的插件示例，照着改就能跑。

> ⚠️ 一句必要的提醒：插件是可执行代码，运行在主程序里，程序不做沙箱隔离。
> 请不要随意安装来源不明的插件。

## 最后

回头看，这个项目里没有什么特别高深的技术，用的都是能查到的方案。
真正花时间的，是那些「不试一次就不知道」的细节：

有些接口的行为和文档写的不一样；有些参数在中文环境里会出问题；
有些看起来是权限问题的故障，其实是网络抖动。

这些我全部记在了仓库的文档里。如果你也在做一个需要长期维护的桌面应用，
希望这些记录能帮你少走一段。
